# ТЗ: новый AI-бот для tk-webb.ru (замена бота на Make)

Подготовлено GEO/AEO-агентом (папка `Seo`) как хендофф-бриф для сессии, которая будет разрабатывать бота в этой папке. Дата: 2026-08-10.

## Контекст

Текущий бот (@firstTKbot) сделан на Make (no-code) — роутер на ключевые слова, заранее прописанные ветки ответов. Подходил под старую версию сайта (лендинг, 5 блоков).

Сайт вырос до **32 страниц**. Роутер с фиксированными ветками больше не может покрыть весь объём контента — под каждый возможный вопрос пришлось бы вручную прописывать ветку, это не масштабируется.

Нужен бот с базой знаний по всему контенту сайта (RAG — retrieval-augmented generation), который сам находит релевантный кусок текста и отвечает на его основе, а не выбирает из заранее прописанных шаблонов.

## Что бот должен уметь

1. Отвечать по любой из 32 страниц сайта (сайты, боты, кейсы, цены, FAQ, статьи), опираясь на реальный контент страниц
2. Держать контекст диалога — не повторять уже сказанное, не терять нить разговора
3. Не вываливать полный прайс сразу на "привет" — сначала 1-2 уточняющих вопроса (что нужно: сайт/бот, какая ниша, что важно), потом релевантный ответ под конкретную задачу
4. **Критично:** когда пользователь сигнализирует готовность ("оставить заявку", "хочу заказать", "давайте оформим") — бот должен сразу и прямо запросить контакт (телефон/telegram-юзернейм) и подтвердить, что будет дальше ("отвечу в течение часа" и т.п.) — **не** просить заново текстом описать задачу
5. Собранные заявки должны долетать до владелицы — пересылка в личный Telegram или запись в таблицу/базу

## Технический подход (ориентир, решает разработческая сессия)

- Источник знаний: контент всех 32 страниц tk-webb.ru (спарсить с живого сайта либо взять исходники, если лежат в этой же папке)
- Telegram Bot API + поиск по эмбеддингам (векторный поиск) по контенту страниц + LLM для генерации ответа на основе найденного релевантного куска
- Предусмотреть переиндексацию базы знаний при обновлении контента сайта — чтобы не пересобирать всё вручную при каждой новой статье

## Что взять из старого бота

- Стартовое приветствие и первый уточняющий вопрос были нормальные, можно использовать как основу:
  > "Могу помочь с сайтом на Tilda или Telegram-ботом. Что вам нужно: сайт-визитка, корпоративный сайт, интернет-магазин или бот?"
- Существующая ссылка на бота: @firstTKbot (можно оставить того же бота технически, просто заменить логику, либо сделать нового — на усмотрение разработческой сессии)

## Найденные проблемы старого бота (зафиксировано на реальном скриншоте диалога 2026-08-10)

- На простое "Привет" бот сразу вываливал полный прайс на сайты и ботов без единого уточняющего вопроса
- Дважды подряд повторил почти одинаковые цифры про типы ботов (нет памяти в рамках диалога)
- На фразу пользователя "оставить заявку можно?" (явный сигнал готовности купить) бот ответил "Напишите, что нужно: сайт или Telegram-бот, и коротко опишите задачу" — вместо прямого запроса контакта. Это провал в момент максимальной готовности клиента — приоритет №1 к исправлению
- У бота нет фото профиля/аватарки в Telegram — снижает доверие с первого взгляда

## Не забыть

- Протестировать реальный диалог перед тем как включать на сайте вместо старого бота
- Проверить, что бот не выдумывает цены/условия, которых нет на сайте (частая проблема плохо настроенного RAG — галлюцинации)
- После завершения — вернуться в сессию GEO/AEO-агента (папка `Seo`) с результатом для проверки и заключения
